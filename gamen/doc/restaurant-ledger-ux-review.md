## 2. レストランボード（Restaurant BOARD）

### 2.1 概要
- リクルートの予約台帳アプリ。画面は**「スケジュール」（時間軸の台帳）・「予約リスト」・「テーブル管理」**の3つで、ワンタッチで切り替えます【確認: App Store説明】
- ホットペッパーグルメ（HPG）と唯一の公式連携があります。HPGのネット予約は自動で取り込まれ、空席はHPGに自動で反映されます。Airレジとも連携します【確認】
- App Store の評価は 4.4（約7,500件）【確認: APPLION】。評価件数が非常に多いアプリです

### 2.2 店側画面の良い点（公式情報とヘルプから）
- スケジュール画面は「縦＝テーブル、横＝時間」で、**5分単位か15分単位の表示幅**を選べます【確認: ヘルプ「スケジュール画面について」】
- 背景色で受付状態を分けています: **グレー＝営業時間外、ピンク＝予約受付可能時間、ピンクの斜線＝確保時間**【確認: ヘルプ】
- 予約バーには「人数・氏名・アイコン」が出ます。アイコンは8種類（要確認客、コース、要望・メモ、HPG経由、メール取り込み、ポイント利用、スマート支払い、電話AI経由）【確認: ヘルプ】
- 「未割り当ての予約」の行があり、テーブルが決まっていない予約がまとまって見えます【確認】
- テーブル名の横に「来店済」が出ます。「業務連絡」にはバッジが付きます。「退店管理」画面もあります【確認】
- テーブル管理では、制限時間の残りが設定値以下になると**オレンジ色で注意**を出します【確認: ヘルプ「基本設定する」】
- ダブルブッキング警告と変更履歴があります【確認】

### 2.3 店側画面の使いにくい点［レビュー］
- **ダブルブッキング時に段が分かれて見づらい**。「段を変えずに重ねて色を付けてほしい」（App Store）
- iPad版で予約名を変えても、テーブル管理・予約リスト・スケジュールに反映されない（App Store, 2020年）
- 動作が重い。電話の対応中や来店時に卓情報が出るまで待たせてしまう（App Store）
- ログインを何度も求められる。パスワードのコピペでログインできない（2025年）
- 「色分けを増やしてほしい」「時間あたりの表示幅が広くて使いづらい」「指定日を予約不可にする方法がわかりにくい」（AppMatchの要約）
- 「顧客情報の統合」が、実際には片方を削除しているだけに見える（App Store）

### 2.4 機能の好評点・不満点［レビュー］
- 好評: HPGの予約が自動で入り、顧客リストも自動で貯まる。初来店かリピートかを自動で判別してくれる。Airレジへの取り込みがスムーズ（ITreview）
- 好評: 席レイアウトが目で見てわかりやすく、アルバイトにも伝えやすい（ITreview）
- 不満: **サイトコントローラーがない**ため、他のグルメサイトとの在庫を全部開けられない。他社媒体の予約は「確認のみ」で、キャンセルや人数変更は元のサイトで行う必要がある（ITreview）
- 不満: スマホ版では顧客情報が紐付かない（2019年）。集計がスマホで見られなくなった（App Store）

### 2.5 画像からの所感［画像からの所感］
見た画像: `restaurantboard_appstore_ipad_1〜5.png`（出典: App Store スクリーンショット 1〜5枚目）

**使いやすそうな点**
1. **現在時刻の赤い縦線と▼マーカー**（ipad_1 の中央 x≈420 の縦線。ヘッダーの「20:00」の下に赤い▼）。【抽出】#E41E24。台帳で一番見たいのは「今」なので、太すぎない1〜2px の線で時間ラベルと結び付けているのはよいと思います
2. **予約バーの右に付いた灰色の「準備時間」**（ipad_1 の (690,520) 付近。赤いバーの右端に灰色の短い帯）。【抽出】#B4B4B4。「片付けの時間がこの席に食い込んでいる」ことが、文字を読まずに見えます
3. **テーブル管理のカードの「経過時間タイマー」**（ipad_3。カード中央の大きい「0:02」「2:12」）。残りが少ないとオレンジになります（「2:12」「1:02」はオレンジ、通常は濃いグレー）。iPadから1〜2m離れても読める大きさ（推定 28〜32pt）で、ホール担当が一目で判断できます
4. **カードの下に赤枠で「次:21:00〜」**（ipad_3 の各カード下段）。次の予約の時刻を空席のカードにも出しているので、「今案内してよいか」をその場で判断できます
5. **右側の「席情報」パネルをタブで「今日の予約」と切り替える**（ipad_3 の右 x≈700〜900）。カード一覧を残したまま、選んだ卓の詳細を出せます

**ここは違うのでは、と思う点**
1. **予約バーの色の意味が画面の中で説明されていない**（ipad_1。赤 #EE3E44・緑 #2DA555・青 #1A6AB4・白地に青枠のバーが混ざっている）。凡例が見当たりません。赤は「要連絡」や「警告」にも使われがちなので、「赤＝来店済み？遅刻？」と迷いそうです → **改善案**: ヘッダー右に「凡例」ボタンを置き、ステータスの色は5色以内に絞ります。赤は「遅刻・要対応」だけに使います
2. **ピンクの受付時間帯の背景（#FFF2F0）と、赤い予約バーの色が近い**（ipad_1 の上4行）。背景が赤っぽいので、赤いバーの「警告感」が弱くなります → **改善案**: 受付時間帯は背景色ではなく、時間軸ヘッダーに細い帯（高さ4px）で出します。グリッドの背景は白かごく薄いグレーにします
3. **テーブル列の縦書き「来店済」「掲載中」**（ipad_1 の x≈270〜290 の細い縦書き）。幅が約12pxしかなく、縦書きの3文字は読みにくいです → **改善案**: テーブル名の左に 8px の色付きドット（緑＝着席中）を置き、テキストはツールチップに回します
4. **左サイドバーのアイコンにラベルがない**（ipad_1 の x≈140 の濃いグレー #595959 の帯。家、封筒、チェックリスト、机、横棒…）。新人には「机のアイコン＝テーブル管理」が分かりにくいと思います → **改善案**: アイコンの下に 10pt のラベルを付けます（食べログノートのサイドバーのように）
5. **集計ダッシュボードの数字の色**（ipad_4。「430名」などが細い灰色の大きい文字）。重要な数字なのに細く薄いので、遠くからは読みにくいです → **改善案**: 数値は #1F2937 の太字（600）にし、前月比は「▲1.2%」と色と記号の両方で出します

### 2.6 改善提案
- ダブルブッキングは**同じ行の中で重ねて表示**し、重なった部分に赤い斜線を付けます（レビューの要望そのまま）
- 予約名の変更は全画面に即時反映します（全画面で同じデータを使い、更新を配信する設計にします）
- 他媒体の予約も、台帳から変更・キャンセルできるようにします（無理なら「元のサイトで変更」ボタンと、未処理のバッジを出します）
- ログインの保持時間を店舗端末用に長くし、PINコードでの再ロックに切り替えます

## 3. トレタ（トレタ予約台帳）

### 3.1 概要
- 「かんたん、シンプル、使いやすい」が方針の**iPad専用アプリ**【確認: App Store説明】。登録店舗は10,000以上【確認】
- 機能: 音声録音・手書きメモ・写真、電話の受付時に来店回数を表示、SMS、無料のウェブ予約ページ、レイアウト図での受付、系列店での共有、CTI（オプション）【確認】
- 20以上のグルメサイト、10社以上のPOSと連携【確認: 公式】。AI電話の「トレタ予約番」【確認】
- 最近の更新: 「タイムテーブル／テーブルレイアウトで長押しすると予約・ウォークインを登録」（v51）、「ブロックの最短時間を15分に」（v50）、「タイムテーブルにネット予約の受付枠を表示」（v60）【確認: App Store 更新履歴】
- App Store の評価 3.4（52件）【確認】

### 3.2 店側画面の良い点
- ドラッグ＆ドロップで配席できる。「テトリスのような操作感」【確認: 飲食店ハックの紹介】
- 事故防止アラート（ダブルブッキング・営業時間外）【確認】
- **ウォークインは2タップで登録**【確認】
- 変更履歴を全部残し、「誰がいつ変えたか」がわかる【確認】
- 顧客名の横に、いつも来店回数が出る【確認】

### 3.3 店側画面の使いにくい点［レビュー］
- **予約を完了した画面が、入力画面とあまり変わらない**。電話をしながら他の作業をしていると、最後まで終わったか分からないまま流れてしまい、予約が漏れたことがある（店長のnote）
- v35 で色の濃さが変わり、**メモ欄の文字が薄くて見えない**（App Store。開発元が改善すると回答）
- メッセージ送信の「送信先を選択する」が画面の下で切れて押せない（2017年）
- 予約ページの見せ方がテキストだけで、コース写真が出せない（比較動画の指摘。予約者側の話なので参考程度）

### 3.4 機能の好評点・不満点［レビュー］
- 好評: 「操作性は圧倒的にトレタ」「スマホを使っている感覚で誰でも使える」「画面のデザインがやわらかくてとっつきやすい」「1階層でパッと操作が終わる」（note。TableCheckと比べてトレタを選んだ店長）
- 不満: 月額が高め。オプション（グルメサイト自動取り込み・予約番・API）を足すと費用がかさむ。iPadが必要（FitGap、飲食店ハック）
- 不満: グルメサイトとの在庫連携が思ったより複雑、多店舗の一元管理がしにくい、という声もある（代理店ブログ。競合の代理店なので割り引いて読む必要あり）

### 3.5 画像からの所感［画像からの所感］
見た画像: `toreta_appstore_ipad_1〜5.png`（App Store。**画面が2016年ごろの古いデザイン**）、`toreta_web_Daicho_01.png`・`Daicho_02.png`・`Daicho_03.png`・`toreta_web_daicho_img_2.png`（公式サイト toreta.in の製品画像。2023年の日付が写っている新しい画面）

**使いやすそうな点**
1. **タイムテーブルの左端の「色付き縦線」で席の種類をまとめている**（Daicho_01 の x≈158 の縦線。VIPルーム＝緑青 #23B697、個室1〜6＝赤 #E44F54、個室7〜＝黄 #E6AF2E【抽出】）。行をグループで区切る見出し行を使わずに、エリアが分かります
2. **予約バーの上の段に「19:00-4名様」と小さく、下の段に「といけんたろう様」と大きく**（Daicho_01 の (300〜480,140)）。上下2段の文字で、時刻と人数はバーの位置を見なくても読めます
3. **最上段の「ウェイティングリスト」行**（Daicho_01 の (100,110)）。順番待ちを台帳と同じ画面に置いていて、ウォークインの多い店に向いています
4. **予約バーの後ろの薄い色の「延長／片付け」部分**（Daicho_01 の青いバーの右、#64A3E2 の薄い版）。レストランボードの灰色の準備時間より、本体と同じ色の薄い版なので「どの予約の続きか」が分かりやすいです
5. **ホーム画面の「新規予約」「予約変更」の大きい2ボタン**（toreta_appstore_ipad_1 の (300〜520,330〜490)）。電話を取った瞬間に押すボタンが2つしかないので、迷いません。青い受話器＝新規、赤い受話器＝変更と色も分けています
6. **予約タグのチップ**（ipad_2 の (300〜540,330〜470)。「席指定」「移動不可」「誕生日」「女子会」など）。キーボードを使わずにタップだけで条件を付けられます。選んだ「移動不可」だけ緑地に白い文字で目立ちます
7. **手書きメモ**（ipad_3）。電話を受けながらペンで書けて、紙の台帳から移るときの抵抗が少ないと思います

**ここは違うのでは、と思う点**
1. **タイムテーブルのヘッダーが黄緑で、時間軸の見出しが灰色の帯**（Daicho_01 の上部。ヘッダーの黄緑と、時間ラベル「17:00」の灰色の帯 #AAAAAA に白い文字）。灰色の地に白い文字はコントラストが約2.3:1しかなく、時刻が読みにくいです → **改善案**: 時間軸は白地 #FFFFFF に #374151 の 13pt 太字にします。正時の線は #D1D5DB、30分の線は点線にします
2. **予約バーの色が「灰色」「青」「緑」の3色だけで、意味が画面上で分からない**（Daicho_01。灰色のバーが多い）。灰色は普通「終わった／無効」に見えるので、もし灰色が「来店前」なら誤解を生みます（推定） → **改善案**: 来店前は白地＋色の枠、着席中は塗りつぶし、退店済みは灰色、のように「塗り方」で状態を表します
3. **予約完了の画面が入力画面と見分けにくい**（レビューの指摘。ipad_2 の下のステップバー「日付／人数 › テーブル選択 › 詳細 › 確認」は分かりやすいが、完了後の見た目は画像では確認できず） → **改善案**: 完了したら、画面の中央に緑のチェックと「予約を登録しました 6/14 18:00 8名 T11」を 1.5秒出し、そのあと台帳に戻って該当のバーを2回点滅させます
4. **App Store の画像が2016年ごろのまま**（ipad_1〜5。iOS 7風のステータスバーと「2016年6月14日」）。今の画面（Daicho_01）とかなり違うので、導入を考えている店が誤解すると思います → **改善案**: 画面の改修に合わせてストアの画像も更新します

### 3.6 改善提案
- 予約登録の完了を、色・アイコン・音で、入力中の画面とはっきり区別します
- メモ欄の文字はいつも #1F2937 以上の濃さにして、薄い灰色を使いません
- 下部のボタンは画面の安全領域（セーフエリア）の中に置き、キーボードを出しても隠れないようにします

2. **フロアのテーブルの色が多すぎて意味が読めない**（ipad_1。水色 #2AABB5、くすんだ黄 #97903F、くすんだピンク、灰色、黄土色が混ざっている）。マニュアルでは「黄＝1件、ピンク＝複数、青＝進行中」ですが、画面の中に凡例がなく、くすんだ色同士は区別しにくいです → **改善案**: 色は「空席／予約あり／着席中／会計待ち／ブロック」の5つだけにし、フロアの右上に凡例を常に出します
3. **左のナビの紫 【抽出】#7C39D3 と、「本日」ボタンの紫が同じ**（ipad_2 の左上）。「今どの画面にいるか」と「今日の日付を見ている」が同じ色なので、意味が重なっています → **改善案**: ナビの選択中は左に4pxの縦線と白い文字にし、「本日」は枠線のボタンにします
4. **上部の小さい数字の並び（「組 36 W 0 … 名 101 0 0 82 19」）**（ipad_1〜4 の左上 (200〜310,230〜245)）。何の数字か、ラベルがとても小さくて読めません → **改善案**: 「予約 36組／101名」「着席 19組」のように、ラベルと数字を1組ずつカードにします
5. **現在時刻の線が暗い赤 【抽出】#8A2F34 で背景に沈んでいる**（ipad_2 の x≈357）。ダークの背景では見えにくいです → **改善案**: 明るい赤 #FF4D4F の 2px の線と、時刻ラベル「12:52」を上に付けます

- 「かんたんモード」を用意して、チャートの1本のバーの情報を減らし、ステータスを5つにまとめます（細かいステータスは詳細モードで使えるようにします）

### 5.2 店側画面の良い点（画像と公式から）
- 台帳の上に「メインフロア」「テラス席」などの**フロアのタブ**があります【確認: 画像】

### 5.5 画像からの所感［画像からの所感］
見た画像: `ebica_appstore_ipad_1〜4.png`（App Store 1〜4枚目）

**使いやすそうな点**
1. **時間軸が2段（「17時 18時 …」の茶色い段＋「0 15 30 45」の段）**（ipad_1 の (370〜830,270〜285)）。15分ごとの区切りが数字で見えるので、「18:15開始」などの細かい時刻を合わせやすいです
2. **予約バーの中が「名前[人数]」＋小さいアイコン**（ipad_1。例「ヨシダ 様[1名]」）。文字の量が少なく、TableCheckより読みやすいです
3. **レイアウト画面で、上に時間のスライダー（15時〜18時の15分刻み）**（ipad_2 の上部）。時刻を選ぶと、その時刻の席の状態が見えると考えられます（推定）。「19時に何卓空くか」をフロアで確かめられます
4. **右のリストの各予約に、オレンジの「ご来店」ボタン**（ipad_2 の右 (720,385) など）。来店処理が1タップで済みます

**ここは違うのでは、と思う点**
1. **予約バーの色がオレンジ・ピンク・水色・灰色・黄緑の5色で、意味が分からない**（ipad_1。【抽出】オレンジ #F6A517、赤紫 #D04385、水色 #10AAE3、灰青 #A6B7BF、黄緑）。予約経路の色なのか、状態の色なのか、画面からは読めません。特に黄緑のバーに白い文字は読みにくいです → **改善案**: 色は「状態」だけに使い、予約経路（食べログ・一休など）はバーの左上の小さいロゴで出します。文字の色は背景の明るさで自動的に白か黒に切り替えます
2. **レイアウト画面の背景が木目の写真**（ipad_2。床の木目、植物、トイレのマークまで描いた写実的な間取り）。見た目はきれいですが、**卓の色（緑・赤・青緑の丸）が木目に埋もれて、空席か使用中かを読むのに時間がかかります**。卓の中の文字は推定 6〜7pt 相当で、とても小さいです → **改善案**: 背景は無地のごく薄いグレー #F5F5F4 にして、壁と入口だけを線で描きます。卓は大きくして、中に「卓番号（太字）・人数・経過時間」の3つだけを出します
3. **顧客詳細が「灰色のラベルのセル＋値」の表を縦にずらっと並べた形**（ipad_3）。灰色のセル（推定 #EEEEEE）が全部同じ重さで並び、「注意事項」「お客様ノート」のように**接客で一番大事な情報が、住所や勤務先と同じ扱い**になっています。右上の写真も大きすぎます → **改善案**: 一番上に「名前・来店回数・注意事項（赤い帯）・タグ」をまとめたカードを置き、勤務先・住所は折りたたみます
4. **左のナビの一番下に「お知らせ」「サポート」が白いボタンで並んでいる**（ipad_1 の (210,550〜580)）。ナビの他のボタン（茶色の四角いアイコン）と形が違い、浮いて見えます。営業中に使う機能でもありません → **改善案**: 設定と同じ「その他」のメニューに入れます
5. **黒い右下の時計＋「ON」ボタン**（ipad_1 の (750〜830,630)）。何がONなのか、ラベルがありません（ネット受付のON/OFFなら重大な操作です）（推定） → **改善案**: 「ネット予約受付: ON」と文字で書き、OFFにするときは確認を出します

### 5.6 改善提案
- 安定性を最優先にします。「操作中」のロックは、端末が落ちたら数十秒で自動的に外れるようにし、「別の端末で操作中です（○○さん、30秒前）」と表示します
- アプリの移行は営業時間外に行い、店ごとに日時を選べるようにします
- 初期設定は「おすすめ設定」から始めて、あとで細かく変えられるようにします

2. **予約バーが「本体の濃い色＋同じ色の薄い延長部分」**（ipad_1。オレンジ #FFBB58 → 薄いオレンジ #FFE6B5、ピンク #F09FB8、水色 #A0D6EA、紫 #D9B4E6【抽出】）。トレタと同じく、延長部分がどの予約のものか分かります
3. **バーの中のチップ「コース」「メモ」とアイコン**（ipad_1）。白い小さいチップに黒い文字で、色付きのバーの上でも読めます
4. **人数の丸いバッジ「④」「⑨（子3）」**（ipad_1 の各バーの左端）。人数を最初に読ませているのは正しいと思います。子ども連れの人数まで出ています
5. **予約登録をすると、空いている卓に「＋」の点線の枠が出る**（ipad_2 の (400〜650,470〜740)）。オレンジの点線の枠で「ここに入れられます」とはっきり見せていて、どこに入れるか迷いません
6. **画面の下の中央に浮かぶ「本日のネット予約を止める」ボタン**（ipad_1 の (510,722)。【抽出】青緑 #3B9DB4 の角丸ピル）。忙しいときに一番使いたい操作を、いつも同じ場所に出しています
7. **フロアマップの右のリストで、ステータスがボタンの色で分かる**（ipad_4。「来店前」＝オレンジ、「着席済み」＝カーキ #CAC0A1、「退店済み」＝灰色）。押すとプルダウンで次の状態へ変えられる形です
8. **左のサイドバーのアイコンにラベルが付いている**（ipad_1。「予約」「フロアマップ」「通知一覧」「分析」「顧客一覧」「設定」）。選んでいる項目はオレンジ #FF8F00【抽出】
9. **ランチ（太陽）／ディナー（月）の切り替えボタン**（ipad_1 の (100,128)・(157,128)）。アイコンで直感的です

**ここは違うのでは、と思う点**
1. **予約バーの色が7色ぐらいあって、何の色か分からない**（ipad_1。オレンジ・ピンク・水色・黄緑・紫・青い左帯・赤い左帯）。左の「a」「b」の縦帯（青・赤）も意味が分かりません → **改善案**: 色の意味を1つ（状態）に決め、凡例をヘッダーに出します。「a」「b」がグループ予約なら、バー同士を線でつなぎます
2. **フロアマップのテーブルの色が薄く、状態がほとんど見えない**（ipad_4。水色 #D6F4FF、薄い黄 #FFE6B5、ベージュの灰 #E7E5DE、ほぼ白のピンク #FFF8F7）。白い背景 #FAF8F5 との差が小さすぎて、少し離れると全部白く見えます → **改善案**: 着席中は濃い塗り（例 #F59E0B）に白い文字、予約ありは白地に色の太い枠（3px）にします
3. **フロアマップの卓の中が「時刻＋人数の丸」を縦に並べるだけ**（ipad_4。例 T5「12:00 ④(子1) 21:00 ④」）。「今座っているのか」「次がいつか」が区別できません → **改善案**: 上に「着席中: 経過0:45」、下に「次 19:00 ④」と、ラベルを付けて分けます
4. **ネット予約ブロックの「操作できません ⓘ」**（ipad_5 の (940,540)）。なぜ操作できないのかが、もう1回タップしないと分かりません → **改善案**: 「食べログの管理画面で作られたブロックのため、ここでは変更できません［食べログで開く］」と、理由と行き先をその場に書きます
5. **退店処理と準備時間の扱い**（レビューの不満。画像の ipad_2 でも延長部分が次の「＋」枠と重なっている (615,470〜740)） → **改善案**: 退店したら準備時間を自動で短くし、準備時間との重なりは「警告（黄色）」にとどめて登録はできるようにします

### 6.6 改善提案
- 通知は「開いたら確認済み」「全部確認済みにする」ボタンを付けます。同じ予約の通知は1件にまとめます
- 顧客メモは、予約バーを1回タップしたシートの一番上に出します
- 当日のネットでの変更は、店の設定で「当日は電話のみ」にできるようにします

### 7.5 画像からの所感［画像からの所感］
見た画像: `opentable_appstore_ipad_1〜2.png`（App Store「OpenTable for Restaurants」1〜2枚目）、`opentable_web_ac8843bbc70e88568d2345cbac474b50.webp`（公式サイトの製品画像。フロアプランの一部）

**使いやすそうな点**
1. **リストを「Waitlist / Reservations / Seated」の見出しで区切り、見出しの右に組数と人数**（ipad_2 の右側。「Reservations 👥4 👤10」）。今何組待っているかが、見出しを見るだけで分かります。見出しは折りたためます（右の ^ ボタン）
2. **リストの1行が「左の状態アイコン → 人数・時刻 → 名前（太字）→ アイコン → 右の卓番号の箱」**（ipad_2）。名前は推定 17pt の太字で、離れても読めます。右端の卓番号の箱は、着席中なら緑 【抽出】#2F864D、別の状態なら水色 #61BDDB に塗られます
3. **左端の状態アイコンを色付きの四角にしている**（ipad_2 の (481,612) のピンク 【抽出】#D82C82、(481,727) の黄色）。色だけでなく形（アイコン）も違うので、色が分かりにくい人にも区別できます
4. **待ち時間のボタン「3h+ 1」「3h+ 2」…**（ipad_2 の Waitlist の下）。待ち客を大きいタイルで並べていて、タップしやすい大きさ（推定 約 50×50pt）です
5. **フロアプランの卓を「卓の形＋状態の色＋中のアイコン」で表す**（web画像。紫 #B362BD、薄紫、オレンジ #FCA631、緑 #62B486、青 #8192E3、灰色【抽出】）。卓の左に「A」「BC」などのサーバーのセクションの小さい札が付いていて、誰の担当か分かります
6. **予約の詳細画面の右の列が「Booked（状態）」→「Table 114, 115 Suggested」→「Send Deposit request」→「Message guest」の縦のボタン**（ipad_1 の右側）。次にやる操作が上から順に並んでいて、迷いません。状態の「Booked」は青緑の塗りのプルダウンで一番目立ちます
7. **Exclude party from pacing limit（ペース制限から外す）のトグル**（ipad_1 の右下）。現場の例外操作を、深いメニューに入れずに予約の画面で切り替えられます

**ここは違うのでは、と思う点**
1. **ダークの背景に紫・薄紫・オレンジ・緑・青の卓が混ざり、色の数が多い**（web画像）。状態の種類（Seated / Entree / Dessert / Check Dropped / Paid …）を全部色にしているので、色の数が8つぐらいになり、覚えきれません → **改善案**: 色は「段階」（来店前→着席→食事中→会計→片付け）の5つにし、Entree・Dessert などの細かい段階は卓の中のアイコンだけで出します
2. **リストの行のアイコンが小さくて多い**（ipad_2 の名前の右。ナイフとフォーク、卓、ケーキ、吹き出し、カード…）。1行に4〜5個並ぶと、どれが大事か分かりません → **改善案**: アイコンは2つまで（アレルギーと記念日を優先）にし、残りは「+3」とまとめます
3. **ゲスト詳細の左上の「7:00 PM」「3」「2h 00m」が、同じ形の白い箱**（ipad_1 の上部）。時刻・人数・滞在時間が同じ見た目なので、押して変えられるのか、表示だけなのかが分かりません → **改善案**: 変えられるものには ▼ を付けるか、ラベル（「時刻」「人数」「滞在」）を箱の上に付けます

### 7.6 改善提案
- フロアプランの設定は「テンプレートを選ぶ → 卓をドラッグ → 人数を入れる」の3ステップのウィザードにします
- iPad・スマホ・Webで同じ部品と同じ色を使います（デザインシステムを共通にします）

1. **グリッドの予約ブロックが全部同じ灰色**（ipad_2 の右。「Jacqueline Johnson」「Arabella Pratt」…がどれも灰色の箱）。状態の違いは左の小さい丸いアイコンだけなので、**グリッド全体を見たときに「着席中」と「来店前」の分布が見えません** → **改善案**: ブロックの塗り方を状態で変えます（来店前＝枠だけ、着席＝塗り、遅刻＝黄色の左帯）

3. **卓の角を回す・大きさを変えるハンドル（オレンジと青の点）**（ipad_1 の 3-A〜3-D の周り）。指で触る点としては小さすぎ（推定 直径 8pt 程度）、iPadで正確に触るのは難しいと思います → **改善案**: ハンドルの当たり判定を 44pt 四方にし、見た目は 12pt にします
4. **チャット画面の濃い灰色の吹き出しに灰色の文字**（ipad_4）。背景 #3A4250 付近（推定）に薄い灰色の時刻で、時刻がとても読みにくいです → **改善案**: 時刻は #9CA3AF 以上の明るさにします

- 縦向き・横向きの両方に対応します（台帳は横、ウェイトリストは縦が使いやすい、などの選択肢を残します）

### 11.2 見習うべきデザインパターン
1. **「今」を赤い1本の線で示す**（レストランボード、SevenRoomsは青い線）。時間軸の見出しにも▼を付ける
2. **予約バーは「人数 → 名前 → アイコン2つ」だけ**（ebica・トレタ）。それ以上は長押しで見せる
3. **延長や片付けの時間を「同じ色の薄い版」で付ける**（トレタ・食べログノート）
4. **「未配席」「席が未確定」を一番上の行か下のバーに数字で出す**（食べログノート・TableCheck）
5. **入れられる空きを点線の「＋」の枠で見せる**（食べログノート）
6. **台帳を隠さず、右から出るシートで登録する**（食べログノート・レストランボード）。OpenTable の調査でも「ゲストカードがフロアを隠すのが嫌」という声がありました
7. **経過時間・待ち時間を「数字＋色＋バーの長さ」で見せる**（SevenRooms・レストランボード）
8. **リストの見出しに組数と人数を出し、たためるようにする**（OpenTable・Resy）
9. **状態は色だけでなく形（アイコン）でも見せる**（OpenTable・Resy）
10. **電話を取ったときのボタンは2つだけ（新規・変更）**（トレタ）
11. **タップだけで付けられる予約タグのチップ**（トレタ）と、**手書きのメモ**（トレタ・ebica）
12. **一番使う「ネット予約を止める」を浮かぶボタンにする**（食べログノート）
13. **ダーク／ライトの切り替え**（TableCheck・OpenTable）。照明の暗い店はダーク
14. **変更の記録（誰がいつ）**（トレタ・SevenRooms）

### 11.3 避けるべきアンチパターン
1. **凡例のない色**（ほぼ全サービス）。色の意味が予約経路なのか状態なのか分からない
2. **色が多すぎる**（TableCheck のフロア、ebica・食べログノートのバー、OpenTable の卓）。5色を超えると覚えられない
3. **1本のバーに情報を詰め込む**（TableCheck のチャート）
4. **写真や木目の背景**（ebica のレイアウト）
5. **薄すぎる状態の色**（食べログノートのフロア）
6. **灰色の地に白い文字の時間軸**（トレタ。コントラスト 約2.3:1）、**ダークで暗い赤の現在線**（TableCheck）
7. **重なると行が分かれる**（レストランボードのダブルブッキング）
8. **ルールが厳しすぎて登録できない**（食べログノートの準備時間）。警告にとどめて、店の判断で入れられるようにする
9. **完了が分かりにくい**（トレタ）
10. **保存が見えない**（Resy のフロア編集）
11. **端末ごとに見た目が違う**（OpenTable のレビュー）、**iPad版とiPhone版でデータの反映が違う**（レストランボードのレビュー）
12. **何度もログインを求める**（レストランボード）、**自動で更新されない**（Resy）
13. **営業中のアップデートや移行**（ebica のレビュー）
14. **ラベルのないアイコン**（レストランボードのサイドバー）、**とても小さいラベル**（SevenRooms のナビ）
